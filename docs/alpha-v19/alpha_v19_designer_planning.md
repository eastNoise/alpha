# ALPHA v19 기준 앱 기획안

> 디자이너 전달용  
> 기준 버전: **V19 — 오늘 상태 카드 제거 버전**  
> 목적: 디자인 시안 제작 전, 앱의 기능/구조/UX 의도를 명확히 공유하기 위한 문서

---

## 1. 앱 한 줄 정의

**ALPHA는 사용자가 매일 루틴을 수행하고, 30일 과정 안에서 자기통제와 상남자 마인드셋을 쌓아가는 앱이다.**

이 앱은 일반적인 습관 체크 앱이 아니라, 사용자가 매일 자기 자신과의 약속을 지키고 그 기록을 쌓아가도록 만드는 **30일 루틴 과정 앱**이다.

---

## 2. 핵심 컨셉

### 핵심 감성

- 강함
- 자기통제
- 루틴
- 절제
- 기록
- 30일 과정
- 하루하루 쌓이는 변화

### 피해야 할 감성

- 게임처럼 보이는 점수/레벨/XP
- 과한 알파메일/픽업 느낌
- “명령”, “증명” 같은 오글거리는 용어의 과다 사용
- 자기혐오, 모욕, 자해 암시
- 너무 헬스 앱처럼 보이는 구성
- 너무 일반적인 Todo 앱처럼 보이는 구성

### 제품 방향

사용자는 앱에 들어와서 이런 느낌을 받아야 한다.

> “오늘도 내가 나를 잡아야겠다.”  
> “작게라도 끝내야겠다.”  
> “30일 동안 내가 변하고 있다.”

## 3. 주요 용어 정리

V19 기준으로 앱 내 주요 용어는 담백하게 가져간다.

| 기존 강한 용어 | 최종 UI 용어 |
|---|---|
| 명령 | 오늘 |
| 증명 | 기록 |
| 프로토콜 | 과정 |
| 개인 명령 | 개인 루틴 |

# 5. 앱 주요 기능

## 5.1 오늘의 불씨

### 기능 설명

홈 화면 상단에 매일 하나씩 랜덤으로 보여주는 동기부여 문구 영역이다.

상태별 문구가 아니라, **하루 전체를 관통하는 대표 문장**이다.  
사용자가 루틴을 몇 개 완료했는지와 상관없이 하루 동안 같은 문구가 유지된다.

### 목적

- 앱에 들어오는 순간 동기부여 제공
- ALPHA 브랜드 톤 형성
- 하루 시작의 감정적 트리거 역할

### 예시 문구

- 기분 따위에 명령권을 넘기지 마라.
- 말보다 강한 건 끝낸 기록이다.
- 몸을 움직여라. 생각은 따라온다.
- 오늘을 장악해라.
- 욕망에 끌려가지 마라.
- 흔들려도 이어가라.
- 너 자신을 지배해라.

### UX 규칙

- 하루에 하나만 노출
- 같은 날에는 고정
- 다음 날 랜덤 변경
- 같은 문구가 너무 자주 반복되지 않도록 관리
- 상태별 문구는 사용하지 않음

---

## 5.2 오늘 루틴

### 기능 설명

현재 사용자의 30일 과정과 현재 단계에 맞는 루틴을 보여주는 핵심 체크 영역이다.

오늘 화면에는 현재 단계까지 누적된 루틴이 전부 표시된다.

### 예시

BASIC Day 1–7일 때:

- 물 500ml
- 침대 정리
- 푸쉬업 30개

BASIC Day 8–14일 때:

- 물 500ml
- 침대 정리
- 푸쉬업 30개
- 스쿼트 30개
- 걷기 10분

### 사용자 행동

- 루틴 항목을 탭하면 완료 처리
- 다시 탭하면 완료 취소
- 완료된 항목은 시각적으로 구분
- 오늘의 완료 수가 요약 영역에 반영됨

### UX 목적

- 사용자가 오늘 해야 할 일을 한눈에 파악
- Todo 앱처럼 보이되, 일반적인 할 일보다 “과정의 일부”처럼 느껴져야 함
- 루틴이 매주 조금씩 늘어나면서 성장감을 제공

---

## 5.3 하루 마감

### 기능 설명

오늘 루틴을 어느 정도 수행했는지 확인하는 마감 기능이다.

사용자가 `하루 마감` 버튼을 누르면 완료 여부를 확인한다. 미완성이라면 기록을 생성하기 전에 한 번 더 선택하게 한다.

### 결과 유형

#### 완료

모든 루틴을 완료한 경우.

예시 문구:

- 완료. 오늘의 기준을 지켰다.
- 기준을 지켰다. 기록은 남았다.
- 오늘의 너는 행동으로 말했다.

#### 미완성

일부 루틴을 완료하지 못한 경우.

마감 전 확인 문구:

- 아직 2개 남았다.
- 이대로 마감하면 오늘은 미완성으로 기록된다.

결과 화면에는 `미완성.`과 완료·미완성 개수만 표시하고 별도 평가 문구를 넣지 않는다.

### 이후 액션

- 미완성 확인: 돌아가기 / 미완성으로 마감
- 마감 결과: 닫기 / 하루 회고 작성하기

### UX 목적

- 하루를 그냥 지나가지 않고 마감하게 함
- 성공/실패를 과하게 벌주지 않고 차갑게 기록
- 오늘 기록 기능으로 자연스럽게 연결

---

## 5.4 오늘 기록

### 기능 설명

사용자가 하루에 대한 짧은 문장을 남기는 기능이다.

일기장이라기보다, **오늘의 나를 한 줄로 남기는 마인드셋 기록**이다.

### 입력 방식

- 한 줄 또는 짧은 문장 중심
- 길게 쓰는 일기가 아니라 짧은 선언/다짐/기록
- 성공한 날도, 실패한 날도 작성 가능

### 성공한 날 예시

- 어제의 나를 이긴 나는 더 강해진다.
- 오늘은 도망치지 않았다.
- 푸쉬업 30개가 쉬워졌다. 몸이 변하고 있다.

### 실패한 날 예시

- 오늘은 미뤘다. 내일은 먼저 움직인다.
- 무너졌지만 숨지 않았다. 기록은 남겼다.
- 내일은 책부터 끝낸다.

### UX 규칙

- 강제 입력 아님
- 하루 마감 후 작성 유도
- 기록 화면에서 다시 확인 가능
- 기록 모음 페이지에서 전체 기록 확인 가능
- 30일 기록 상세에서도 해당 날짜의 오늘 기록 확인 가능

---

## 5.5 개인 루틴 추가

### 기능 설명

기본 과정 루틴 외에 사용자가 직접 루틴을 추가할 수 있는 기능이다.

### 위치

- 오늘 화면
- 기록 화면

과정 화면에는 넣지 않는다.  
과정 화면은 큰 30일 구조를 보여주는 곳이고, 개인 루틴은 매일 행동하는 화면에서 관리하는 것이 더 자연스럽다.

### 입력 항목

- 루틴명
- 카테고리
  - 몸
  - 정신
  - 절제
  - 집중
  - 생활
- 적용 범위
  - 오늘만
  - 이번 과정 동안

### 적용 범위 설명

#### 오늘만

해당 날짜에만 표시되는 일회성 루틴.

예시:

- 과제 제출
- 방 청소 20분
- 병원 예약

#### 이번 과정 동안

현재 30일 과정 동안 계속 표시되는 개인 루틴.

예시:

- 턱걸이 10개
- 아침 물 1L
- 영어 단어 20개

### 내부 로직

개인 루틴은 화면에는 표시하지만, BASIC → STANDARD → HARD 과정 판단용 내부 달성률에는 포함하지 않는 방향이 적절하다.

이유:

- 사용자가 너무 어려운 개인 루틴을 추가하면 승급이 불리해질 수 있음
- 너무 쉬운 루틴을 추가하면 달성률이 왜곡될 수 있음
- 기본 과정의 루틴만 과정 판단 기준으로 삼는 것이 안정적임

# 6. 30일 과정 시스템

## 6.1 기본 규칙

모든 사용자는 처음부터 BASIC으로 시작한다.

사용자가 BASIC / STANDARD / HARD를 직접 선택하지 않는다.

### 과정 흐름

1. BASIC 30일
2. STANDARD 30일
3. HARD 30일

각 과정은 30일 단위로 진행된다.

### 내부 통과 기준

UI에는 노출하지 않는다.

- BASIC: 내부 달성률 50% 이상이면 STANDARD 오픈
- STANDARD: 내부 달성률 70% 이상이면 HARD 오픈
- HARD: 내부 달성률 90% 이상이면 전체 과정 마감
- 기준 미달 시 같은 과정 30일 재시작

디자이너에게 중요한 점은, 이 조건을 화면에 직접 보여주지 않는다는 것이다.  
사용자는 “기록으로 다음 과정이 열린다” 정도만 느끼면 된다.

30일차 마감 뒤 회고까지 저장하면 홈의 주 CTA가 결과에 맞게 바뀐다.

- BASIC 통과: `STANDARD 과정 시작`
- STANDARD 통과: `HARD 과정 시작`
- HARD 통과: `친구에게 앱 공유하기`
- 기준 미달: 현재 과정 결과를 보여주고 같은 과정 재시작 경로 제공

공유는 선택 행동이며 HARD 완료 여부나 기록 보존에 영향을 주지 않는다. Google Play 개발자 계정 이전은 완료됐지만 공개 상세 페이지가 아직 확인되지 않았으므로, 실제 다운로드 URL이 확정될 때까지 공유 링크 설정값을 비워둔다.

# 7. 기록 기능

## 7.1 기록 화면 역할

기록 화면은 전체 통계 화면이 아니라, 사용자가 자신의 루틴 흐름과 오늘 기록을 확인하는 공간이다.

### 포함 요소

- 연속 완료
- 오늘 루틴 완료 현황
- 30일 과정 기록 카드
- 최근 기록
- 흔들린 부분 / 강한 부분
- 오늘 기록
- 기록 모음 진입

---

## 7.2 30일 과정 기록 카드

기록 화면에는 30일 기록을 전부 펼쳐놓지 않는다.  
요약 카드만 보여주고, 상세 페이지로 이동하게 한다.

### 카드 정보

- 현재 과정명
- 현재 Day n/30
- 완료일
- 미완성일
- 30일 기록 보기 버튼

### 목적

- 기록 화면을 복잡하게 만들지 않음
- 30일 기록은 별도 페이지에서 중요하게 보여줌

---

## 7.3 30일 기록 상세 페이지

### 기능 설명

현재 30일 과정의 기록을 상세하게 보는 페이지.

### 포함 요소

- 현재 과정명
- Day n/30
- 진행률
- 완료일 수
- 미완성일 수
- 30일 그리드
- 과정 단계 카드

### 30일 그리드 상태

- 완료
- 미완성
- 오늘
- 예정

### 날짜 상세

그리드의 날짜를 누르면 바텀시트가 열린다.

포함 정보:

- Day 번호
- 날짜
- 상태
- 해당 단계명
- 해당 날짜의 기본 루틴 목록
- 기본 루틴 완료 현황
- 해당 날짜의 오늘 기록

---

## 7.4 기록 모음 페이지

### 기능 설명

사용자가 작성한 오늘 기록을 날짜별로 모아보는 페이지.

### 포함 요소

- 남긴 기록 개수
- 날짜별 기록 리스트
- Day 번호
- 완료/미완성 상태
- 기록 문장

### UX 목적

- 사용자가 자신이 남긴 문장들을 다시 보며 변화감을 느끼게 함
- 루틴 체크보다 감정적 유대감을 만드는 기능
- 앱 재방문 이유 강화

# 8. 과정 화면

## 역할

과정 화면은 사용자가 현재 어떤 30일 과정 안에 있는지 보여주는 화면이다.

### 포함 요소

- 현재 과정명
- 현재 Day n/30
- 진행률
- 30일 기록 페이지 진입
- 4단계 과정 카드
- 다음 과정 상태

### 삭제해야 할 것

- BASIC / STANDARD / HARD 선택 카드
- 사용자가 난이도를 직접 고르는 구조
- 통과 조건 숫자 노출

### 다음 과정 표시

다음 과정은 “잠김” 또는 “열림” 정도로만 표현한다.

예시:

- STANDARD — 잠김
- HARD — 잠김

숫자 조건은 표시하지 않는다.

# 9. 설정 화면

설정은 최소한으로 유지한다.

### 포함 요소

- 문구 톤
  - 기본
  - 하드
  - 냉정
- 알림 ON/OFF
- 탭 피드백 ON/OFF
- 상황별 알림 구조 안내

### 상황별 알림 예시

앱이 나중에 알림을 보낼 때는 사용자의 진행 상태를 기준으로 다르게 보낸다.

- 아직 시작 전: 아직 아무것도 지우지 않았다.
- 진행 중: 남은 루틴이 있다.
- 완료 후: 오늘은 도망치지 않았다.
- 흔들릴 때: 기준이 흔들리고 있다.

# 11. 디자인 시 유의사항

디자인 방향은 따로 시안에서 결정하되, 기능 기획상 다음 원칙은 유지하면 좋다.

1. 앱 용어는 담백하게 유지한다.
2. 문장은 강하게 가져간다.
3. 점수/XP/랭킹은 넣지 않는다.
4. 30일 과정이 중심처럼 보여야 한다.
5. 오늘 기록이 쌓이는 느낌이 중요하다.
6. 루틴 체크는 단순하지만, 과정 안에서 의미 있어 보여야 한다.
7. 너무 헬스 앱처럼 보이지 않게 몸/정신/절제/기록이 균형 있게 보여야 한다.
8. 사용자가 선택할 것은 적게, 앱이 안내하는 과정은 명확하게 한다.
9. 실패를 모욕하지 않는다. 대신 기록으로 남긴다.
10. 상남자 감성은 유지하되 UI는 지나치게 오글거리지 않게 한다.

# 13. 최종 제품 방향

ALPHA는 “습관 체크 앱”이 아니라, 사용자가 30일 동안 자기 루틴을 쌓고 자신의 문장을 남기는 앱이다.

앱이 성공하려면 사용자가 이렇게 느껴야 한다.

> “내가 30일 동안 바뀌고 있다.”  
> “오늘도 하나는 끝내야 한다.”  
> “내 기록이 나를 보고 있다.”  
> “어제보다 조금 더 단단해졌다.”

디자인은 이 감각을 중심으로 잡으면 된다.
