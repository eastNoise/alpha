# ALPHA v19 과정별 단계 루틴 정리

> 기준: ALPHA v19 현재 프로토콜  
> 구조: BASIC → STANDARD → HARD  
> 각 과정은 30일 단위이며, 4개의 단계로 나뉜다.  
> 단계가 올라갈수록 기존 루틴은 유지되고, 새로운 루틴이 추가되는 **누적 구조**다.

| BASIC | 02 몸 깨우기 | Day 8–14 | 5개 |

# 2. BASIC 과정

BASIC은 첫 30일 과정이다. 사용자가 처음 앱을 시작하면 BASIC 과정으로 자동 진입한다.

## BASIC 01. 기초 통제

**기간:** Day 1–7  
**루틴 수:** 3개

### 루틴

- 물 500ml
- 침대 정리
- 푸쉬업 30개

### 단계 의도

처음부터 과하게 몰아붙이지 않고, 하루를 통제하는 최소 기준을 세우는 단계다.  
몸, 생활, 간단한 행동 루틴을 통해 사용자가 “오늘도 하나는 끝냈다”는 감각을 만들게 한다.

# 5. 구현 시 주의사항

## 5.1 단계 루틴은 누적 구조로 계산한다

각 단계는 새 루틴만 보여주는 것이 아니라,  
**이전 단계 루틴 + 현재 단계 추가 루틴**을 모두 보여줘야 한다.

예시:

```ts
BASIC Day 15–21 = BASIC 01 루틴 + BASIC 02 추가 루틴 + BASIC 03 추가 루틴
```

---

## 5.2 사용자는 난이도를 직접 고르지 않는다

사용자는 BASIC / STANDARD / HARD를 직접 선택하지 않는다.

흐름은 다음과 같다.

```text
BASIC 30일
→ 기준 충족 시 STANDARD 오픈
→ 기준 충족 시 HARD 오픈
```

---

## 5.3 통과 기준은 UI에 직접 노출하지 않는다

내부 통과 기준은 존재하지만, 화면에는 숫자로 직접 보여주지 않는다.

예시:

```text
STANDARD 잠김
HARD 잠김
```

정도로만 보여준다.

---

## 5.4 개인 루틴은 과정 통과율에 반영하지 않는다

사용자가 추가한 개인 루틴은 오늘 화면에는 표시되지만,  
BASIC / STANDARD / HARD 통과 판단에는 포함하지 않는 것이 안정적이다.

이유:

- 너무 어려운 개인 루틴을 추가하면 승급이 불리해짐
- 너무 쉬운 개인 루틴을 추가하면 달성률이 왜곡됨
- 기본 과정 루틴만 기준으로 삼는 것이 가장 안정적임

# 7. 현재 평가

현재 루틴 구조는 다음과 같은 특징이 있다.

- BASIC은 입문용으로 적당하다.
- STANDARD부터 운동과 절제가 본격적으로 들어간다.
- HARD는 꽤 빡센 편이다.
- 단계별로 루틴이 누적되는 구조라 성장감이 있다.
- STANDARD 4단계와 HARD 4단계는 루틴 수가 9개까지 올라가므로, 실제 사용자에게는 부담이 클 수 있다.

MVP에서는 현재 구조로 진행하되, 실제 테스트 후 HARD의 강도는 조정 가능하게 두는 것이 좋다.
